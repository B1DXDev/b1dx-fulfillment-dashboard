⚠️
อัปเดต 2026-07-16: Lazada รองรับแค่ 8/17 สถานะทางการ — 8 ใน 9 ที่ขาดมีความเสี่ยง regression
Report นี้สรุปจากโค้ดที่มีอยู่เท่านั้น (7 status group ที่ handled) — ยังไม่เคยเทียบกับ Lazada Order Status Catalog ฉบับทางการ (17 สถานะ) พอเทียบแล้วพบว่า repacked, ready_to_ship_pending, failed_delivery, shipped_back, shipped_back_success, shipped_back_failed, lost_by_3pl, damaged_by_3pl ไม่มี case ใน LazadaOrderParser.MapStatus() เลย — ตกไป fallback 200 เหมือน unknown status ทั่วไป ซึ่งถ้า order นั้น progress ไปไกลกว่า 200 แล้ว (490/500/600) จะถูกดึงสถานะกลับมา PendingReview ทันที นอกจากนี้ OMS มี ReturnInitiated=560/ReturnReceived=630 รองรับ shipped_back/shipped_back_success อยู่แล้วแต่ parser ยังไม่ใช้ — รายละเอียดเต็ม + worksheet สำหรับ business review อยู่ที่ lazada-status-coverage-gap.html
🔀
Lazada เท่านั้นที่มี "Confirmed" (300) เป็น step แยก
Shopee และ TikTok ไม่ส่งสถานะ "ยืนยันออเดอร์" แยกจาก pending — กระโดดจาก 200 (PendingReview) ไป 490 (ReadyToShip) ตรง ๆ เมื่อร้านเริ่มแพ็ค ส่วน Lazada มี confirmed คั่นกลางก่อนเข้าสถานะแพ็ค
📦
Shopee เท่านั้นที่มี "OutForDelivery" (550) จาก marketplace โดยตรง
Shopee ส่ง TO_CONFIRM_RECEIVE ตรงมาที่ 550 — Lazada/TikTok ไม่มี raw status สำหรับ 550 เลย ต้องพึ่ง courier webhook (spx/jnt/flash/kex tracking event) เพื่อขยับ order ไปที่ 550 แทน (ดู order-state-machine.md § courier override)
✅
Lazada ไม่มี raw status ที่แปลว่า "Completed" (700)
Lazada parser จบสุดที่ delivered → 600 เท่านั้น — ไม่มี case ไหน map ไป 700 ตรง ๆ ต่างจาก Shopee (COMPLETED) และ TikTok (COMPLETED) ที่มี terminal-success status ส่งมาจาก platform เอง แปลว่าออเดอร์ Lazada ต้องถูกปิดจบด้วย action ภายใน OMS (complete) แทน ไม่ใช่จาก webhook
⏸️
Shopee เท่านั้นที่มี "CancelRequested" (750) แบบ interim
Shopee มี IN_CANCEL เป็นสถานะ "กำลังขอยกเลิก" ก่อนตัดจริงที่ CANCELLED — Lazada/TikTok ไม่มี interim state นี้ ยกเลิกแล้วตกไป 800 ทันที (ไม่มี "รอ approve" จาก marketplace)
⚠️
Shopee ไม่มี "Returned" (900) mapping ในเวอร์ชันนี้
ต่างจาก Lazada (returned) และ TikTok (RETURNED/RETURN_REFUND) — Shopee parser เวอร์ชันปัจจุบันไม่มี case ไหน map ไป 900 หรือ payment_status = refunded เลย ถ้า Shopee ส่ง return event มาในอนาคต จะตกไปที่ fallback 200 + log warning แทน ควรตรวจสอบว่า Shopee API มี return status จริงหรือยัง แล้วเพิ่ม case ให้ parser
🧩
TikTok รวม 3 raw status เข้า 490 เดียว
ON_HOLD, AWAITING_SHIPMENT, READY_TO_SHIP ทั้งหมด map ไป 490 (ReadyToShip) เหมือนกัน — เป็น platform เดียวที่รวม "ออเดอร์ค้าง/พักไว้" (ON_HOLD) เข้ากับ "พร้อมส่ง" กลุ่มเดียว ต่างจาก Shopee/Lazada ที่แยกชัดกว่า
