Objective

เมื่อ order จากมาร์เก็ตเพลส (Lazada / Shopee / TikTok) sync เข้าสู่ OMS แล้ว แต่ละ order item จะมาพร้อม seller SKU code ที่ผู้ขายตั้งเองบนแพลตฟอร์ม ซึ่ง OMS ยังไม่รู้ว่าตรงกับ internal product ตัวไหน — ต้องผ่านขั้นตอน "จับคู่" (matching) ก่อน order ถึงจะยืนยัน (confirm) และเข้าสู่กระบวนการคลัง/จัดส่งได้ รายงานนี้สรุป flow ตั้งแต่ webhook รับ order จนถึงจับคู่ SKU สำเร็จใน OMS พร้อมอธิบายเหตุผลเชิงธุรกิจว่าทำไมต้องมีขั้นตอนนี้

จับคู่ Order Item + SKU — ทำเพื่ออะไร

Marketplace ส่ง order item มาด้วย seller SKU code ของแต่ละแพลตฟอร์มเอง (string อิสระที่ผู้ขายตั้งเอง) ซึ่ง OMS ไม่รู้จักว่าตรงกับ internal product ตัวไหนในระบบ — ต้องจับคู่ก่อนถึงจะทำงานต่อได้

1 · Gate บังคับก่อนยืนยัน Order (BR-02)

ถ้า order item ไหน match_status = unmatched ระบบจะปฏิเสธการเปลี่ยนสถานะ จาก MatchPending (100) → Confirmed (400) ทันที (HTTP 409) — order จะไปต่อสู่ขั้น allocate/pick/pack ไม่ได้จนกว่าจะจับคู่ครบ

2 · ผูก Order Item เข้ากับ Product Master จริง

เมื่อจับคู่แล้ว ระบบรู้ product/stock/attribute เบื้องหลัง SKU นั้นจริง — จำเป็นสำหรับ downstream ทั้งหมด: ตัด stock, pick queue, ราคา, รายงาน เพราะ logic เหล่านี้ทำงานบน internal product ID ไม่ใช่ seller SKU string ที่อาจไม่ตรงกับ catalog จริง

3 · Auto-Match ก่อน แล้ว Fallback เป็น Manual (ระบบ "เรียนรู้")

ทุก order ที่ sync เข้ามาจะพยายาม auto-match กับ oms.sku_mappings ก่อนเสมอ:

เจอ mapping → matched อัตโนมัติ → ไม่เจอ (SKU ใหม่) → unmatched/partial → Manual match 1 ครั้ง → บันทึกกลับ sku_mappings → auto-match ได้เองในอนาคต
✅ สรุปสั้นๆ: จับคู่ = แปล "SKU ของผู้ขายบนแพลตฟอร์ม" ให้กลายเป็น "product จริงใน OMS" ซึ่งเป็นเงื่อนไขบังคับก่อนที่ order จะยืนยันและเข้าสู่กระบวนการคลัง/จัดส่งได้
