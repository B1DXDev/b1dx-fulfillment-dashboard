PLAN 5 priorities เรียงตาม impact

คลิกเพื่อขยายรายละเอียด · % เป็น estimate ต่อ lever ไม่ additive ตรงๆ แต่รวมกันถึง target 50–70%

1 Context Hygiene — ตัด session ที่ลากยาวข้าม task
~30–40%
 ▶
  • จบ task → /clear ก่อนเริ่ม task ใหม่ที่ไม่เกี่ยวกัน — 90% >150k กับ 78% 8+ ชม. คือสัญญาณเดียวกัน
  • เช็ค context ก่อนรัน fork-heavy skill (/review, ultrareview) — ถ้าบวมจาก exploration รอบก่อน ให้ /clear ก่อน ไม่งั้นทุก fork call แบก context เก่าไปฟรีๆ
  • ห้าม Read log/build-output/spec ยาวเข้า main context — ให้ subagent อ่าน+สรุปกลับมาแทน

อ้างอิง: agents/_shared/token-efficiency.md § Read & Search, § Subagent Delegation

2 Subagent Right-Sizing — เลือก agent type + model ตาม scope จริง
~15–20%
 ▶
  • Pure lookup/grep-scope → Explore ไม่ใช่ general-purpose (tool set เล็กกว่า = เบากว่าโดย design) — general-purpose กิน 16% ของ subagent cost
  • ทุก dispatch subagent ต้อง map ผ่าน Effort Control Matrix จริง (ดู section ถัดไป) ไม่ปล่อย default opus/think-hard ให้งาน risk LOW
  • Research <3 query → ไม่ต้อง spawn agent เลย ใช้ Grep/Glob ตรงในเทิร์นหลัก

อ้างอิง: agents/workflow-router.md § Effort Control Matrix (บรรทัด 255–277) · agents/orchestrator.md § 6.2.1

3 Tool / RTK Discipline
~10–15%
 ▶
  • Cross-shell command (git/dotnet/gh/npm) → ยิงผ่าน Bash tool เสมอ (RTK proxy เซฟ ~94% เฉพาะทางนี้) สงวน PowerShell เฉพาะที่ Bash ทำไม่ได้จริง
  • เช็ค compliance เป็นระยะ — rtk gain --failures หา bare head/tail/grep -r ที่หลุด filter
  • ไฟล์ >500 บรรทัด → Grep หา section ก่อนเสมอ ห้าม Read เต็มไฟล์

อ้างอิง: agents/_shared/token-efficiency.md § RTK, § Read & Search

4 ตัดงานซ้ำ — dedup subagent spawn + re-derivation
~5–10%
 ▶
  • ก่อน spawn subagent เช็คว่ามี agent เรื่องเดียวกันรันอยู่ไหม → SendMessage ต่อแทน spawn ใหม่
  • ห้าม re-derive fact ที่คุยไปแล้วในเทิร์นก่อน หรือ re-litigate decision ที่ user ตัดสินใจแล้ว
  • Batch independent tool call ในเทิร์นเดียวเสมอ — ลด round-trip

อ้างอิง: agents/_shared/token-efficiency.md § Subagent Delegation
